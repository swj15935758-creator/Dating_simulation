## 1. 프로젝트 개요
- **주제:** AI 페르소나를 가진 NPC와 음성 또는 텍스트로 대화하면서 관계를 발전시키는 3개 에피소드형 연애 시뮬레이션 게임.
- **해결하려는 문제:** 선택지가 고정된 게임과 달리 사용자가 자신의 말로 대화하면서 NPC의 반응을 경험하고, 표현 방식·배려·상대방의 선호를 생각해 볼 기회가 부족함. 대화 내용의 문맥과 이전 장면의 기억이 관계 변화에 반영되도록 구현한다.
- **연애 가이드·대화 경험:** 사용자의 발화를 인사·취향·약속·감상평·고백 등으로 분석하고, 캐릭터별 선호·비선호와 호감도·신뢰도에 연결해 다양한 반응과 엔딩을 제공한다. 실제 연애 성공이나 행동 개선을 보장하는 서비스가 아닌 체험형 게임으로 설계한다.
- **목표 사용자:** 대화형 AI·캐릭터 게임에 관심이 있는 성인 이용자, 다양한 의사소통 상황을 가상으로 체험하고 싶은 이용자.
- **개발 목표 및 기대 효과:** 회원가입부터 캐릭터 선택, 음성 대화, 3개 에피소드 진행, 엔딩, 기록 저장·이어하기까지 하나의 실행 가능한 서비스 구현. NPC 성격의 일관성, 이전 대화 기억, 근거 있는 점수 변화, 오류 대응을 검증한다. 대화 방식에 관한 재미와 탐색 경험은 기대 효과이며, 저출산 해결 등 사회적 효과는 검증되지 않은 목표로 성공 기준에 포함하지 않는다.
- **프로젝트 범위(포함):**
  - 회원가입·로그인, 필수 동의, 이메일 6자리 인증번호 발송·확인(회의 설계안), 언어 선택(기본 `ko`), 성인 대상 이용 정책.
  - 캐릭터 성별 버전 선택, 공통 페르소나 로딩, 캐릭터별 이미지·목소리·호칭 적용.
  - 고정 에피소드 3개: **EP1 카페(14시)** → **EP2 영화 후 산책(17시)** → **EP3 포차(19시)**. 장면별 배경·BGM·환경음과 대화 목표 적용.
  - 사용자 음성 녹음·STT 변환·인식 결과 수정 또는 텍스트 입력, AI 문맥 분석과 템플릿 중심 NPC 응답, TTS 음성 출력.
  - 호감도·신뢰도(각 0~100, 초기 0점), 캐릭터별 가중치·반복 점수 방지, EP 해금·관계 종료·고백·수락·거절·멀티 엔딩.
  - 이전 대화·전체 기억·중요 기억 관리, 게임 상태와 점수·엔딩 이력의 PostgreSQL 저장·조회·이어하기.
  - Perso API를 이용한 **사전 제작 영상의 번역·더빙 및 재생**(적용 범위·비용 확인 필요), 발표용 3개 장면 시연 영상.
- **프로젝트 범위(제외 또는 후순위):** 사진 첨부, 무제한 자유 시나리오 생성, 장기 기억 고도화, 관리자 대시보드, 고급 음성 스트리밍. 부적절한 성인 표현의 제한 정책을 정하고 적용한다.
- **자료 간 차이 및 검토 사항:**
  - 캐릭터 수: 11/23 회의안은 **공통 유형 A·B × 남/여 = 화면 선택 4종**. Word 문서의 다른 부분은 **A·B·C × 남/여 = 6종** 및 9개 공통 에피소드/18개 플레이 조합을 설명한다. 기존 기획서의 'NPC 4명'과 함께 최종 확정이 필요하다. 동일 유형의 남녀 버전은 성향·점수 규칙을 공유하고 이미지·이름·음성 등을 분리한다.
  - 지원 언어: 초기 기획은 **한국어·영어·중국어·일본어(ko/en/zh/ja) 4개 언어**. 최신 회의 메모에는 전체 지원 범위가 확정되어 있지 않아 실제 STT/TTS·UI·영상 지원과 함께 검증한다.
  - 관계 수치: EP1 통과 호감도 **30 / 신뢰도 20**, EP2 통과 **40 / 50**은 테스트용 기준안. EP별 6유효턴·1턴 ±10 변화량도 임시안이다.
  - 사용자 연령/인증: 이메일 인증은 메일 소유 확인이며 **성인 본인확인과 동일하지 않다**. 실제 성인 확인 수단과 수집할 개인정보 범위를 결정해야 한다.
  - 점수 화면 공개 범위, 음성 원본 보존, 전체·중요 기억 저장 시점, 언어별 Perso 미디어 지원 여부도 미확정이다.

- **GitHub 운영:** 개인 `feature/*` 브랜치에서 작업하고 공용 브랜치 반영은 PR 검토 후 진행한다. `main` 직접 Push·강제 Push는 원칙적으로 금지하며, 통합 책임은 PM·API·통합 역할에 둔다.

## 3. 기술 스택
| 구분 | 기술 | 선정 이유 |
|---|---|---|
| 프론트엔드 | Python, **Streamlit** | 캐릭터·대화·에피소드·엔딩 화면을 빠르게 구현하고 UI 상태를 관리 |
| 백엔드 | **Python, FastAPI, Pydantic**, SQL | API 라우팅·입력 검증·응답 형식 표준화, 게임·점수·저장 로직의 계층 분리. API 서버 배포 방식은 추후 확정 |
| AI 모델/API | **OpenAI LLM**, STT, TTS, **Perso API** | 발화 문맥/의도 분류와 응답 생성, 음성 입력·출력, 사전 제작 영상의 번역·더빙. STT/TTS 구체 모델은 비교 후 확정 |
| 데이터 저장 | **PostgreSQL (NeonDB 사용안)** | 사용자·NPC·게임·대화·기억·점수·엔딩 이력의 관계형 저장 및 트랜잭션 처리 |
| 배포 | **Streamlit Community Cloud**(UI 후보) + API 실행 환경(미정) | 웹 시연·외부 접속. **Streamlit Cloud에 FastAPI가 자동 배포되는 것은 아니므로** 별도 API 호스팅/연결 방식을 결정해야 함 |

- **설계 형태:** Presentation(Streamlit) → API(FastAPI) → Service(게임·대화·점수) → Repository(DB), Service → External Client(STT/LLM/TTS/Perso) 구조의 **Layered Architecture**.
- **주요 DB 데이터:** `users`, `user_profiles`, `user_consents`, `characters`, `character_variants`, `episodes`, `game_sessions`, `conversations`, `score_logs`, `character_memories`, `media_assets`, `game_endings` 등은 **설계 후보**이다. 11/24의 `allmemory`, `keymemory` 별도 테이블안과 매핑해 ERD에서 확정한다.
- **핵심 처리 기준:** `system` 메시지에 NPC 규칙·현재 장면·기억을 구성하고 `user` 발화를 분석한 뒤, `assistant` 응답을 생성한다. 점수 계산은 LLM 제안 결과를 그대로 적용하지 않고 Python 규칙·범위·중복 검증을 거친다.

## 5. 성공 기준 및 위험
- **핵심 기능 완료 기준:**
  1. 회원가입·동의·인증·로그인 후 유효한 NPC를 선택하고 EP1을 시작할 수 있다.
  2. 마이크 또는 텍스트 입력 → STT 결과 확인·수정 → LLM 문맥 분석 → 검증·점수 보정 → NPC 응답/TTS가 연결된다.
  3. 호감도·신뢰도는 0~100 범위로 유지되고 중복 턴·불확실한 발화에 부당한 점수가 반영되지 않는다.
  4. EP1·EP2 통과/실패 및 EP3 고백·수락·거절이 정해진 기준대로 분기되고, 성공·친구·불안정·실패 엔딩을 구분한다.
  5. 사용자별 게임·대화·점수·기억·엔딩이 DB에 저장·조회되고 재접속 후 이어하기가 동작하며, 다른 계정·캐릭터 기록이 섞이지 않는다.
  6. 필요한 Perso 미디어를 정상 재생하며 외부 API 실패 시 핵심 플레이가 중단되지 않도록 대체 경로를 제공한다.
- **배포 성공 기준:** 외부에서 배포 URL 접근 → 가입/로그인 → 캐릭터 선택 → 3개 장면 진행 → 엔딩 확인·저장 → 재접속 이어하기를 실행하고, STT·TTS·LLM·DB·미디어 연결 및 비밀키 비노출을 확인한다.
- **예상 위험(API 비용, 개인정보, 일정 등) 및 대응:**
  - **LLM/STT/TTS/Perso 비용·호출 제한:** 요청·출력 크기·횟수·비용 상한을 설정하고 사전 제작 미디어 재사용·오류 시 대체 화면 활용.
  - **개인정보·음성 기록:** 수집·보존·삭제·외부 전송 정책 합의, 이용 동의 분리, 비밀번호 해시 저장, DB 접근 권한 분리. 성인 확인 수단 별도 결정.
  - **모델 오판 및 점수 불균형:** 주체/부정/과거 시제 구분, 구조화 응답 검증, 가중치·범위 보정, 경계값·NPC별 회귀 테스트.
  - **메모리 유실 및 중복 저장:** `st.session_state`에만 보관하는 데이터는 재시작 시 유실 가능. 체크포인트·DB 저장 시점·중복 방지 키·트랜잭션 방식을 구현 전에 결정.
  - **API·배포 장애:** 타임아웃, 제한된 재시도, 오류 안내, 텍스트 응답/대체 미디어, API 서버와 Streamlit 배포 연결 검증.
  - **정책·일정 미확정:** 캐릭터 4종/6종, 지원 언어, 인증, 턴 제한, 점수 임계값, 영상·저장 기준을 D2~D3에 확정하고 변경 사항을 문서·WBS에 동시 반영.
