# HEARTLINE — AI 모델 개발 및 DB 연동 설계서

## 1. 프로젝트 개요

### 1-1. 프로젝트 목적

본 프로젝트는 LLM과 머신러닝(XGBoost)을 결합한 AI 연애 시뮬레이션 서비스이다.

사용자는 AI 캐릭터와 자유롭게 대화하며 관계를 발전시킬 수 있다. LLM은 캐릭터의 페르소나와 이전 대화 맥락을 바탕으로 자연스러운 응답을 생성한다.

또한 LLM이 사용자와 캐릭터의 대화를 분석하여 머신러닝 입력용 특징값을 생성하고, XGBoost 모델이 이를 바탕으로 호감도와 신뢰도의 변화량을 각각 예측한다.

Python 게임 로직은 예측된 변화량을 현재 점수에 반영하며, 총 15턴의 대화가 완료되면 호감도와 신뢰도의 평균 점수에 따라 최종 엔딩을 결정한다.

### 1-2. 전체 시스템 구성

| 구성 요소 | 담당 역할 |
|---|---|
| Streamlit | 캐릭터 선택, 장면 표시, 대화 입력, 에피소드 전환 및 테스트 화면 |
| LLM | 캐릭터 대사 생성 및 대화 내용 분석 |
| Python | 대화 흐름, 특징값 구성, 점수 반영, 턴 및 엔딩 관리 |
| XGBoost | 호감도 및 신뢰도 변화량 예측 |
| FastAPI | XGBoost 모델 실행 및 점수 예측 API 제공 |
| 게임 DB | 향후 사용자, 게임 세션, 대화 기록, 점수 및 엔딩 저장 |

### 1-3. 현재 구현 기준 전체 처리 흐름

1. 사용자가 캐릭터를 선택하고 게임을 시작한다.
2. Python이 게임 상태를 생성한다. 초기 호감도와 신뢰도는 각각 20점이다.
3. 현재 에피소드의 장면 이미지와 고정 설명을 화면에 표시한다.
4. LLM이 캐릭터 페르소나와 에피소드 상황을 참고하여 오프닝 대사를 생성한다.
5. 오프닝 대사는 화면에 표시하지만 턴 수와 점수 분석에는 포함하지 않는다.
6. 사용자가 음성 또는 텍스트로 대화를 입력한다.
7. LLM이 캐릭터의 성격과 이전 대화 맥락을 참고하여 응답한다.
8. 사용자 발언과 캐릭터 응답이 완성되면 LLM이 해당 대화 쌍을 분석한다.
9. LLM이 분석한 6개 특징값에 Python이 계산한 3개 값을 추가하여 총 9개의 특징값을 구성한다.
10. Python이 캐릭터 성격 유형에 맞는 FastAPI 점수 서버에 데이터를 전달한다.
11. XGBoost 모델이 호감도와 신뢰도의 변화량을 각각 예측한다.
12. Python이 예측 변화량을 정수로 변환하여 현재 점수에 반영한다.
13. 에피소드당 5턴이 완료되면 다음 에피소드로 이동할 수 있다.
14. EP3의 마지막 턴이 완료되면 최종 평균 점수를 계산하여 엔딩을 결정한다.

**턴의 정의**

사용자 메시지 1개와 캐릭터 응답 1개가 완성된 대화 쌍을 1턴으로 계산한다.

오프닝 대사는 별도로 표시되는 캐릭터의 첫 대화이며, 전체 15턴에 포함하지 않는다.

## 2. 게임 기본 구조 및 규칙

### 2-1. 게임 진행 구조

| 항목 | 설정 |
|---|---:|
| 전체 에피소드 | 3개 |
| 에피소드당 대화 | 5턴 |
| 전체 대화 | 15턴 |
| 초기 호감도 | 20점 |
| 초기 신뢰도 | 20점 |
| 최소 점수 | 0점 |
| 최대 점수 | 100점 |
| 턴별 호감도 변화량 | -10 ~ +10점 |
| 턴별 신뢰도 변화량 | -10 ~ +10점 |
| 에피소드 진행 | EP1 → EP2 → EP3 |

- 호감도와 신뢰도는 서로 독립적으로 관리한다.
- 한쪽 점수가 상승하더라도 다른 쪽 점수가 반드시 상승하는 것은 아니다.
- 점수와 관계없이 모든 에피소드를 순서대로 진행한다.
- 각 에피소드가 5턴 완료되면 사용자가 버튼을 눌러 다음 에피소드로 이동한다.
- 중간에 점수가 낮아져도 게임이 종료되지 않는다.
- 전체 게임 상태와 대화 기록은 현재 Streamlit의 세션 상태를 통해 관리한다.

### 2-2. 캐릭터 성격 유형

캐릭터는 크게 두 가지 성격 유형으로 구분한다.

**Type A: 안정형**

- 차분하고 안정적인 대화 스타일
- 상대방의 감정을 고려하는 편
- 관계 형성에 신중한 태도
- 일관된 성격과 반응 유지
- 신뢰와 약속을 중요하게 생각함

**Type B: 즉흥형**

- 자유롭고 활발한 대화 스타일
- 감정 표현이 비교적 적극적
- 유머와 새로운 경험을 중요하게 생각함
- 대화 분위기에 따라 다양한 반응 생성
- 예상하지 못한 대화 상황에 유연하게 대응함

각 유형은 남성 및 여성 캐릭터로 구분한다.

- Type A 남성
- Type A 여성
- Type B 남성
- Type B 여성

같은 성격 유형은 성별이 달라도 동일한 유형의 머신러닝 모델을 사용한다.

## 3. 에피소드별 장소 및 진행 방향

### EP1. 첫 만남과 서로 알아가기

**장소: 새서울 종로 루프탑 카페**

**시간: 오후 3시**

- 첫 만남을 통해 서로의 첫인상을 형성한다.
- 카페에서 가벼운 일상 대화를 진행한다.
- 서로의 취향, 관심사, 성격 등을 파악한다.
- 사용자의 대화 방식과 반응에 따라 초기 호감과 신뢰가 형성된다.

**AI 대화 방향**

- 처음 만난 사람과 대화하는 자연스러운 분위기
- 부담스럽지 않은 질문과 가벼운 농담
- 상대방의 취향과 관심사를 파악하는 대화
- 처음부터 지나치게 친밀하거나 무거운 대화는 피함

### EP2. 가까워지는 관계

**장소: CGV 동대문 및 청계천**

**시간: 오후 3시 영화 관람 시작, 약 2시간 관람 후 산책**

- 함께 영화를 관람한 이후 산책하는 상황으로 시작한다.
- 영화 제목, 장르, 줄거리 정보를 활용한다.
- 영화에 대한 감상과 의견을 나눈다.
- 청계천으로 이동하여 산책하며 대화를 이어간다.
- EP1에서 파악한 취향과 관심사를 자연스럽게 활용한다.
- 이전 대화에서 형성된 기억을 바탕으로 관계를 발전시킨다.

**영화 정보 입력**

현재 테스트 앱에서는 영화 정보를 입력할 수 있도록 구성한다.

- 영화 제목
- 영화 장르
- 영화 줄거리

입력된 영화 정보는 LLM의 대화 맥락에 전달하여 영화 감상과 관련된 자연스러운 대화를 생성하는 데 활용한다.

**AI 대화 방향**

- 영화와 취향에 관한 의견 공유
- 이전 대화에서 언급한 내용을 자연스럽게 기억하고 활용
- 일상적인 이야기에서 조금 더 개인적인 이야기로 확장

### EP3. 진심 확인과 관계의 결정

**장소: 종로 포장마차 거리**

**시간: 저녁**

- 포장마차에서 편안한 분위기로 대화를 진행한다.
- 서로의 생각과 감정에 관한 깊은 대화를 나눈다.
- 상대방과의 관계에 대해 진지하게 이야기한다.
- 사용자의 고백 또는 특별한 상황에서 캐릭터의 고백이 발생할 수 있다.
- 대화와 관계 점수를 바탕으로 최종 엔딩을 결정한다.

**AI 대화 방향**

- 감정과 관계에 관한 진솔한 대화
- 이전 에피소드의 기억과 관계 발전 과정 반영
- 고백 및 관계 결정 상황에 맞는 자연스러운 응답
- 고백을 억지로 유도하지 않고 자연스러운 대화 흐름 유지

## 4. LLM 설계

### 4-1. LLM의 역할

LLM은 HEARTLINE에서 두 가지 핵심 역할을 담당한다.

**첫 번째: 캐릭터 응답 생성**

- 캐릭터 페르소나 유지
- 현재 에피소드와 장소 반영
- 사용자 발언에 대한 자연스러운 응답 생성
- 이전 대화 내용과 관계 상태 반영
- 캐릭터 유형에 맞는 말투와 표현 유지

**두 번째: 대화 내용 분석**

- 사용자 발언과 캐릭터 응답을 함께 분석
- 사용자의 감정과 대화 행동 파악
- 캐릭터의 선호도와 일치하는 정도 분석
- 공감, 관심, 진정성 등의 특징값 생성
- 머신러닝 모델에 전달할 6개 특징값 생성

LLM은 실제 호감도와 신뢰도 변화량을 직접 확정하지 않는다.

LLM은 분석에 필요한 특징값을 생성하고, 실제 점수 변화량은 XGBoost 모델이 예측한다.

### 4-2. 캐릭터 응답 생성에 활용하는 맥락

LLM은 다음 정보를 활용하여 응답을 생성한다.

| 항목 | 설명 |
|---|---|
| Persona | 캐릭터 성격, MBTI, 선호도, 비선호도, 말투 |
| Conversation History | 이전 사용자 발언 및 AI 응답 |
| Current Episode | 현재 에피소드 번호 |
| Conversation Count | 현재까지 진행한 대화 횟수 |
| Affection | 현재 호감도 |
| Trust | 현재 신뢰도 |
| Previous Behavior | 이전 대화에서 나타난 사용자 행동 |
| Relationship State | 현재 관계 상태 |
| Memory | 이전 대화에서 기억해야 할 주요 내용 |

현재 테스트 앱에서는 위 정보를 Streamlit의 `st.session_state`를 통해 관리한다.

실제 게임 DB 연동 시에는 DB에 저장된 대화 기록과 관계 정보를 불러오는 구조로 확장한다.

### 4-3. LLM 응답 JSON 구조

캐릭터 응답은 다음과 같은 JSON 형식으로 반환한다.

```json
{
  "reply": "사용자에게 보여줄 캐릭터의 대사"
}
```

Python은 반환된 JSON에서 `reply` 값을 추출하여 Streamlit 화면에 출력한다.

캐릭터 응답과 점수 분석은 별도의 과정으로 처리한다.

## 5. 호감도 및 신뢰도 판단 설계

### 5-1. 호감도(Affection)

호감도는 캐릭터가 사용자에게 느끼는 긍정적인 관심과 연애적 호감의 정도를 의미한다.

주요 판단 요소는 다음과 같다.

- 사용자가 캐릭터에게 관심을 표현하는가?
- 캐릭터의 취향과 선호를 고려하는가?
- 긍정적인 반응과 칭찬을 하는가?
- 대화에 적극적으로 참여하는가?
- 같은 말이나 행동을 반복하지 않는가?

### 5-2. 신뢰도(Trust)

신뢰도는 캐릭터가 사용자에게 느끼는 안정감과 진정성의 정도를 의미한다.

주요 판단 요소는 다음과 같다.

- 상대방의 감정을 이해하고 공감하는가?
- 진정성 있는 대화를 하는가?
- 이전 대화 내용을 기억하고 반영하는가?
- 말과 행동에 일관성이 있는가?
- 상대방의 비선호 요소를 고려하는가?

### 5-3. 호감도와 신뢰도의 차이

| 구분 | 호감도 | 신뢰도 |
|---|---|---|
| 핵심 의미 | 긍정적인 관심과 호감 | 안정감과 진정성 |
| 주요 요소 | 관심 표현, 취향 일치, 긍정적 반응 | 공감, 일관성, 맥락 기억 |
| 상승 예시 | 취향에 맞는 대화, 적극적인 관심 | 감정 공감, 약속 기억 |
| 하락 예시 | 무관심, 반복적인 부정 반응 | 무성의한 태도, 대화 내용의 불일치 |

두 점수는 독립적으로 변화한다.

예를 들어 사용자가 적극적으로 호감을 표현하더라도 상대방의 감정을 이해하지 못한다면 호감도는 상승하고 신뢰도는 하락할 수 있다.

반대로 사용자가 차분하게 공감하고 이전 대화를 기억한다면 신뢰도는 상승하지만 호감도는 크게 변하지 않을 수도 있다.

## 6. LLM 분석 데이터 및 특징값 생성

### 6-1. 분석 시점

LLM 분석은 사용자 발언만 입력된 시점이 아니라 사용자 발언과 캐릭터 응답이 모두 완성된 이후에 실행한다.

분석 대상은 다음과 같다.

- 현재 사용자 발언
- 현재 캐릭터 응답
- 캐릭터 페르소나
- 이전 대화 맥락
- 현재 관계 상태

즉, 한 턴의 사용자 발언과 AI 응답을 하나의 대화 쌍으로 보고 분석한다.

### 6-2. LLM이 생성하는 6개 특징값

LLM은 다음 6개 특징값을 생성한다.

| 컬럼명 | 설명 | 값의 범위 |
|---|---|---|
| `preference_match` | 캐릭터의 선호와 사용자의 발언이 일치하는 정도 | 0~1 |
| `dislike_match` | 사용자의 발언이 캐릭터의 비선호 요소와 겹치는 정도 | 0~1 |
| `empathy` | 사용자가 캐릭터의 감정과 입장을 이해하는 정도 | 0~1 |
| `interest` | 사용자가 캐릭터에게 관심을 표현하는 정도 | 0~1 |
| `sincerity` | 사용자의 발언과 행동이 진정성 있게 느껴지는 정도 | 0~1 |
| `context_match` | 현재 대화가 이전 대화 맥락과 일치하는 정도 | 0~1 |

각 특징값은 0.0~1.0 범위의 숫자로 생성한다.

값이 높을수록 해당 특징이 강하게 나타났다는 의미이다.

단, `dislike_match`는 캐릭터가 싫어하는 요소와 얼마나 겹치는지를 나타내므로 값이 높다고 반드시 긍정적인 의미는 아니다.

### 6-3. LLM 분석 결과 JSON 예시

```json
{
  "features": {
    "preference_match": 0.8,
    "dislike_match": 0.0,
    "empathy": 0.9,
    "interest": 0.8,
    "sincerity": 0.9,
    "context_match": 0.8
  },
  "reason": "캐릭터의 취향을 고려하고 이전 대화를 기억해 진정성 있게 반응함"
}
```

`reason`은 개발자가 분석 근거를 확인하기 위한 설명이다.

실제 XGBoost 모델에는 위 JSON의 6개 숫자 특징값만 전달한다.

### 6-4. Python이 추가하는 3개 특징값

LLM이 생성한 6개 특징값 외에 Python은 다음 3개 값을 추가한다.

| 컬럼명 | 생성 주체 | 설명 | 값의 범위 |
|---|---|---|---|
| `repetition_count` | Python | 최근 사용자 발언의 반복 정도 | 0~3 |
| `previous_affection` | 게임 상태 | 이번 턴 직전 호감도 | 0~100 |
| `previous_trust` | 게임 상태 | 이번 턴 직전 신뢰도 | 0~100 |

**repetition_count**

최근 사용자 발언과 현재 발언을 비교하여 반복 정도를 계산한다.

현재 구현에서는 최근 3개의 사용자 발언을 기준으로 반복 여부를 확인하고, 계산 결과를 0~3 범위로 제한한다.

**previous_affection**

현재 턴의 점수 예측을 실행하기 직전 게임 상태에 저장된 호감도이다.

**previous_trust**

현재 턴의 점수 예측을 실행하기 직전 게임 상태에 저장된 신뢰도이다.

예를 들어 이번 턴 시작 전 호감도가 25점이고 신뢰도가 23점이라면 다음 값이 모델 입력에 포함된다.

```json
{
  "previous_affection": 25,
  "previous_trust": 23
}
```

### 6-5. 최종 머신러닝 입력 특징값

LLM의 6개 특징값과 Python의 3개 특징값을 합쳐 총 9개 특징값을 구성한다.

| 순서 | 컬럼명 | 생성 주체 |
|---:|---|---|
| 1 | `preference_match` | LLM |
| 2 | `dislike_match` | LLM |
| 3 | `empathy` | LLM |
| 4 | `interest` | LLM |
| 5 | `sincerity` | LLM |
| 6 | `context_match` | LLM |
| 7 | `repetition_count` | Python |
| 8 | `previous_affection` | 게임 상태 |
| 9 | `previous_trust` | 게임 상태 |

### 6-6. 최종 입력 JSON 예시

```json
{
  "personality_type": "A",
  "features": {
    "preference_match": 0.8,
    "dislike_match": 0.0,
    "empathy": 0.9,
    "interest": 0.8,
    "sincerity": 0.9,
    "context_match": 0.8,
    "repetition_count": 0,
    "previous_affection": 20,
    "previous_trust": 20
  }
}
```

`personality_type`은 어떤 유형의 모델을 사용할지 결정하는 구분값이며, 9개 특징값에는 포함하지 않는다.

## 7. XGBoost 모델 설계 및 점수 예측

### 7-1. 모델 구성

캐릭터 성격 유형별로 호감도와 신뢰도 모델을 각각 구성한다.

| 모델 | 예측 대상 |
|---|---|
| Type A Affection | Type A 호감도 변화량 |
| Type A Trust | Type A 신뢰도 변화량 |
| Type B Affection | Type B 호감도 변화량 |
| Type B Trust | Type B 신뢰도 변화량 |

총 4개의 XGBoost 모델을 사용한다.

남성·여성 캐릭터는 같은 성격 유형이면 동일한 모델을 사용한다.

### 7-2. XGBoost 입력값 전달 과정

실제 게임에서 모델에 전달되는 과정은 다음과 같다.

1. 사용자가 메시지를 입력한다.
2. LLM이 캐릭터 응답을 생성한다.
3. 사용자 발언과 캐릭터 응답을 LLM에 전달한다.
4. LLM이 6개 특징값을 생성한다.
5. Python이 `repetition_count`를 계산한다.
6. Python이 이전 호감도와 신뢰도를 가져온다.
7. 총 9개 특징값을 하나의 데이터로 구성한다.
8. 캐릭터 유형에 따라 Type A 또는 Type B 모델을 선택한다.
9. FastAPI 점수 서버에 예측 요청을 보낸다.
10. 점수 서버가 호감도 모델과 신뢰도 모델을 각각 실행한다.
11. 예측된 두 변화량을 Python에 반환한다.

### 7-3. 모델 입력 컬럼 순서

모델 학습 시 사용한 특징값 순서와 실제 예측 시 전달하는 순서는 반드시 동일해야 한다.

```python
FEATURE_COLUMNS = [
    "preference_match",
    "dislike_match",
    "empathy",
    "interest",
    "sincerity",
    "context_match",
    "repetition_count",
    "previous_affection",
    "previous_trust"
]
```

컬럼의 순서가 달라지면 모델이 다른 의미의 값을 입력받을 수 있으므로 학습 코드와 예측 코드에서 동일하게 관리해야 한다.

### 7-4. XGBoost 예측 결과

XGBoost는 최종 호감도와 신뢰도를 직접 예측하는 것이 아니라 각각의 점수 변화량을 예측한다.

예시:

```json
{
  "affection_change": 2.7,
  "trust_change": -1.4
}
```

이는 다음을 의미한다.

- 호감도: 약 2.7점 상승
- 신뢰도: 약 1.4점 하락

### 7-5. 정수 변환 및 점수 반영

현재 게임에서는 예측된 변화량을 정수로 변환하여 점수에 반영한다.

각 점수의 변화량은 -10~+10점 범위로 제한한다.

예시:

| 항목 | 현재 점수 | 모델 예측값 | 정수 변화량 | 최종 점수 |
|---|---:|---:|---:|---:|
| 호감도 | 20 | +2.7 | +3 | 23 |
| 신뢰도 | 20 | -1.4 | -1 | 19 |

점수 반영 과정은 다음과 같다.

```python
new_affection = max(
    0,
    min(100, current_affection + affection_change)
)

new_trust = max(
    0,
    min(100, current_trust + trust_change)
)
```

최종 점수는 각각 0~100 범위로 제한한다.

**중요한 점은 LLM이 생성한 특징값을 단순히 더해서 점수를 만드는 방식이 아니라는 것이다.**

예를 들어 `preference_match`가 0.8이라고 해서 호감도가 무조건 8점 상승하는 것은 아니다.

XGBoost는 9개 특징값의 조합과 이전 점수를 학습한 결과를 바탕으로 실제 변화량을 예측한다.

### 8-5. 학습과 실제 게임 실행의 차이

학습 단계에서는 `llm_suggested_affection_change`와 `llm_suggested_trust_change`를 목표값으로 사용한다.

하지만 실제 게임에서는 LLM이 제안한 변화량을 직접 점수에 반영하지 않는다.

실제 게임에서는 다음 순서로 진행한다.

1. LLM이 대화를 분석하고 6개 특징값을 생성한다.
2. Python이 3개 특징값을 추가한다.
3. XGBoost가 학습된 모델을 실행한다.
4. XGBoost의 예측 변화량을 게임 점수에 반영한다.

따라서 학습 데이터의 목표값과 실제 게임에서 사용하는 XGBoost 예측값은 구분된다.

| `repetition_count` | 반복 발언 횟수 |
| `affection` | 현재 호감도 |
| `trust` | 현재 신뢰도 |

### 11-2. 한 턴의 전체 처리 과정

1. **DB에서 정보 조회**
   - 이전 대화 내용
   - 현재 호감도와 신뢰도
   - 캐릭터 유형

2. **LLM에 대화 전달**
   - 사용자 발언
   - 이전 대화 내용
   - 캐릭터 성격 및 취향 정보
   - 위 정보를 바탕으로 캐릭터의 자연스러운 답변을 생성한다.

3. **LLM 대화 분석**
   - 사용자 발언과 대화 맥락을 분석한다.
   - 아래 6개 항목을 0~1 사이의 숫자로 추출한다.

| 분석 항목 | 분석 내용 |
|---|---|
| `preference_match` | 캐릭터 취향과 잘 맞는가? |
| `dislike_match` | 캐릭터가 싫어하는 행동을 했는가? |
| `empathy` | 상대방에게 공감했는가? |
| `interest` | 대화에 관심을 보였는가? |
| `sincerity` | 진정성 있게 대화했는가? |
| `context_match` | 이전 대화와 자연스럽게 이어지는가? |

4. **Python에서 추가 정보 계산**
   - 반복 발언 횟수 계산
   - DB에서 가져온 현재 호감도와 신뢰도 추가
   - 총 9개의 모델 입력값 구성

### 11-3. 모델에 전달하는 데이터 형식

Python은 LLM 분석 결과와 기존 점수 등을 하나의 JSON 형태로 구성해 점수 예측 서버에 전달한다.

```json
{
  "personality_type": "A",
  "features": {
    "preference_match": 0.8,
    "dislike_match": 0.0,
    "empathy": 0.9,
    "interest": 0.8,
    "sincerity": 0.9,
    "context_match": 0.8,
    "repetition_count": 0,
    "previous_affection": 20,
    "previous_trust": 20
  }
}
```

- `personality_type`: A형 또는 B형 모델 선택
- `features`: XGBoost에 전달할 9개 입력값

### 11-4. AI 모델의 점수 계산

1. 점수 예측 서버가 전달받은 캐릭터 유형을 확인한다.
2. 해당 유형에 맞는 XGBoost 모델을 선택한다.
3. 9개 입력값을 모델에 전달한다.
4. 호감도와 신뢰도의 변화량을 각각 예측한다.
5. Python에서 예측값을 정수로 변환하고 -10~+10 범위로 제한한다.
6. 기존 점수에 변화량을 반영하고 0~100 범위로 제한한다.

**점수 계산 예시**

| 항목 | 호감도 | 신뢰도 |
|---|---:|---:|
| 이전 점수 | 20 | 20 |
| 모델 예측 변화량 | +3 | +2 |
| 계산 후 점수 | 23 | 22 |

### 11-5. 계산 결과 DB 저장

모델이 점수 계산을 마치면 Python이 `game` 테이블에 해당 턴의 정보를 저장한다.

예를 들어 첫 번째 대화가 끝나면 다음과 같이 저장된다.

- 사용자 발언
- 이전 대화 내용
- GPT가 분석한 6개 항목
- Python이 계산한 반복 횟수
- 계산이 완료된 호감도와 신뢰도

다음 턴이 시작되면 DB에서 가장 최근에 저장된 호감도와 신뢰도를 가져와 새로운 점수 계산에 사용한다.

### 11-6. 전체 구조 요약

```text
사용자 발언
    ↓
DB에서 이전 대화 및 현재 점수 조회
    ↓
LLM
    ├── 캐릭터 답변 생성
    └── 대화 분석 및 6개 특성값 추출
    ↓
Python
    ├── 반복 횟수 계산
    └── 이전 호감도·신뢰도 추가
    ↓
총 9개 입력값 + 캐릭터 유형
    ↓
점수 예측 서버 (FastAPI)
    ↓
XGBoost 모델
    ├── 호감도 변화량 예측
    └── 신뢰도 변화량 예측
    ↓
Python에서 점수 반영
    ↓
game 테이블에 최종 점수 저장
    ↓
다음 턴에서 저장된 점수 재사용
```

**핵심:** LLM은 대화 생성과 분석을 담당하고, XGBoost는 분석된 데이터를 바탕으로 점수 변화를 예측한다. Python은 두 시스템을 연결하고 최종 점수를 계산하며, DB는 다음 턴에 필요한 대화 정보와 현재 점수를 관리한다.

## 12. 최종 엔딩 규칙

최종 엔딩은 호감도와 신뢰도의 평균 점수만을 기준으로 결정한다.

**최종 평균 점수 = (최종 호감도 + 최종 신뢰도) / 2**

### 12-1. 엔딩 점수 기준

| 엔딩 | 평균 점수 기준 | 엔딩 방향 |
|---|---:|---|
| 연인 엔딩 | 90~100점 | 좋은 관계로 발전하여 연인이 되는 결말 |
| 썸 엔딩 | 80점 이상 ~ 90점 미만 | 서로 호감은 있지만 연인 관계를 확정하지 않은 결말 |
| 친구 엔딩 | 70점 이상 ~ 80점 미만 | 연애 관계가 아닌 친구로 남는 결말 |
| 남남 엔딩 | 0점 이상 ~ 70점 미만 | 관계가 발전하지 못하고 각자의 길을 가는 결말 |

### 12-2. 엔딩 판정 방식

- EP3의 마지막 5번째 대화가 끝나면 엔딩을 판정한다.
- 호감도와 신뢰도의 평균 점수를 계산한다.
- 평균 점수가 속하는 구간의 엔딩을 출력한다.
- 고백 의도나 대화 내용 자체는 엔딩 점수 판정에 사용하지 않는다.
- 사용자가 고백하거나 캐릭터가 고백하더라도 최종 엔딩은 평균 점수로 결정한다.

### 12-3. 엔딩 판정 예시

| 최종 호감도 | 최종 신뢰도 | 평균 점수 | 결과 |
|---:|---:|---:|---|
| 95 | 91 | 93 | 연인 엔딩 |
| 85 | 83 | 84 | 썸 엔딩 |
| 75 | 72 | 73.5 | 친구 엔딩 |
| 60 | 55 | 57.5 | 남남 엔딩 |
| 20 | 30 | 25 | 남남 엔딩 |
